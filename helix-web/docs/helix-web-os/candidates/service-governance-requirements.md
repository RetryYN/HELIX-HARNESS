# HELIX-WEB-OSの要求候補（2026-09-26 PO原案）

## これは何か

2026-09-26にPOが示した「HELIX-Web製品群 要求原案」のうち、HELIX-WEB-OSが担当する部分を、原文のID・種類・文言のまま載せる。
原文の状態は「要求候補・未採択」である。本書は要求（L2）でも受入（L11）でもなく、本書から要求の採用・承認・実装許可を生成しない。

出典は[原文のsnapshot](../../helix-web/sources/helix-web-product-group-requirements-po-original-2026-09-26.md)の13節（snapshot 296〜321行）である。見出しの階層だけを一段下げた。

## 原案の本文

<!-- 出典：snapshot 296〜321行（原案13節） -->
### 13．HELIX-WEB-OSの要求

**目的：Web提供系の案件をバックグラウンドで継続運転し、本体OSの内部状態と分離して管理・推進・検収を成立させること。**

ID接頭辞：`HELIXWEBOS-L2-`  
既存001〜006の意味を上書きせず、007以降を本原案の候補とする。

| 番号・種類 | 要求 | 受入候補 |
|---|---|---|
| **007・単体** | 顧客、利用者、案件、環境、利用製品、予算、許可、対象版を登録・管理すること。 | 同じ共通実装を使っていても、本体OSや他顧客の状態・権限を共有しない。 |
| **008・接続** | Webからの変更受付、CORE処理、設計導出、実行、検証、結果返却をジョブとして管理すること。 | Web画面が閉じても状態を保持し、入力と結果の対応を失わない。 |
| **009・構成体** | HARNESSの契約とCOREの状態から、工程、ticket、依存、優先度、未完義務を管理すること。 | 製品間の移動・再試行・担当交代でも未完義務が消えない。 |
| **010・接続** | LABOの実績とINTELLIGENCEの配置案を用い、役割をレーンへ割り当て、必要なWorkerクラスを指定できること。 | レーンとWorkerを混同せず、利用者の利用可能能力・予算を超えない。 |
| **011・構成体** | 並列実行、利用枠待ち、レビュー待ち、人間判断待ち、停止、再試行、再割当てを管理すること。 | 実作業と待機を区別し、担当交代で重複実行・範囲拡張を起こさない。 |
| **012・構成体** | ticketと変更影響から必要なCI・テスト・独立レビューを導き、結果を検収すること。 | 有効な下位証拠を再利用しつつ、接続・構成体固有の義務を省略しない。 |
| **013・接続** | 独立レビューを作成側と異なるidentity・context・authority・review経路で行えること。 | 作成Worker自身やその内部Subagentの自己評価を独立レビューとせず、providerの違いだけで独立性を決めない。 |
| **014・構成体** | 残作業、依存、並列性、作業実績、再作業、各種待機から完了見込みを算出・更新すること。 | 単一日時の断定ではなく予測幅・前提・遅延要因を示し、予測誤差をLABOへ返す。 |
| **015・構成体** | 取消・停止・権限失効を、実行中・待機中・再接続後の操作へ反映すること。 | 失効前の許可で再開せず、直ちに止められない処理はその状態と封じ込めを示す。 |
| **016・単体** | 原記録からWebへ状態を投影し、遅延・不一致・結果不明を表せること。 | 表示キャッシュや通知だけを実行事実・受入の正本にしない。 |
| **017・接続** | 観測を目的・許可・対象版・時点付きでLABOへ渡すこと。 | 原状態の所有をLABOへ移さず、失敗や欠測も受け渡す。 |
| **018・接続** | LABOから公開用日次集計を受領し、一貫した集計版としてWebへ反映すること。 | 新旧の値を混在させず、集計停止時は最終正常更新と遅延を表示する。 |
| **019・構成体** | 検証済みの製品・機構版を、互換性・依存・設定を確認して段階適用・切戻しすること。 | リリースの存在だけで全案件を更新せず、提供版と案件参照版を区別する。 |
| **020・構成体** | 保存記録から案件・ジョブ・許可・未完義務を復旧できること。 | サービス再起動で作業が重複せず、復旧成功と恒久修復を区別する。 |
| **021・構成体** | 管理・操作系、Worker・CI、統計集計、改善実験の負荷と予算を分離できること。 | 高負荷処理や集計停止で、無関係な顧客案件と制御機能を一律停止させない。 |

Workerの共通契約と独立レビュー条件は、現行本体の定義を再利用する。Web側の案件運転に適用することを、本体OSの運転authorityを共有する根拠にしない。
