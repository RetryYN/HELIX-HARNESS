# HELIX全体の商用ライセンス要求候補

文書版: 0.1。状態: draft candidate。対象Issue: #659、関連: #958 / #1494 / #1500。
本書は契約書ではなく、既存LICENSEの許諾を変更しない。発効版・条文・権利確認は未完了。

## L1: 提供価値と対象

HELIXの独自資産を持続的に開発・保守するため、今後のHELIX全体は有償商用提供を基本とする。
対象は本体、Module、Slice、Bundle、Lite/Full、CLI、独自文書、テンプレート、スキル、学習資産である。
将来のWeb/APIも共通方針へ接続するが、本要求からWeb実装・課金処理・利用監視を開始しない。
単一の共通契約に利用範囲別の追加条件を接続し、機能ごとに独立した契約正本を乱立させない。

HELIXを使って作ったアプリは利用者側の成果物とする。HELIXの使用だけを理由として、
そのアプリ、利用者のプロジェクト、入力、生成成果物の権利をRetryYNへ移転させない。
HELIX自身、Package、Release Pack、Gene等のHELIX独自資産はRetryYN側の資産として扱う。
利用者へ与える利用許諾と所有権移転を区別する。アプリにHELIX資産を同梱する場合も、その部分は
アプリの独自部分と分離して元の許諾を適用する。Packageに含まれる第三者素材までRetryYN所有とは扱わない。
第三者コード・モデル重み・外部データ・providerサービスにはそれぞれの条件がある。
将来の学習資産も、適用可能な権利・同意を確認した独自部分のみ対象にできる。

## 任意の紹介協力

利用者には「Built with HELIX」等の紹介表示を任意で依頼できる。表示、リンク、ロゴの採用は利用者が選び、
不採用・非表示・削除によって利用権、価格、機能、サポートを不利に変更しない。生成アプリへ自動挿入しない。
顧客名、アプリ名、画面、導入事例をRetryYN側の宣伝へ利用する許可は、この依頼とは別に取得する。

## 現行との相違

調査基準main: `0f733a9a034759521ad38ac6b92c8c5a39f7b9a1`。
この版のLICENSEとpackage.jsonはMIT。AGPL＋商用が現行であるという前提は採用しない。
利用実績がないという申告と、既に提供した版の許諾は別に扱う。過去MIT版を新契約で遡及撤回しない。
AGPLは有償契約必須を実現する選択ではない。有償限定の対象版をOSSと表示しない。

## L3: 要件差分候補

以下のCL-Rは本候補内の識別子。承認・正本化前にRequirement IRやruntimeへ直接投入しない。
現行HR-FR-HYB-008 / HR-FR-P6-06のライセンス・来歴・配布検証を拡張する。
商用方針はHELIX全体を覆い、#659の外部配布範囲だけへ縮小しない。

| ID | 要件 |
| --- | --- |
| CL-R-01 | HELIX全体の共通商用方針を定義し、各提供単位を共通契約版へ対応付ける。未所属・二重契約所有を明示する |
| CL-R-02 | 通常利用は有償契約を基本とし、無償評価は明示された対象・期間・用途に限る。評価許諾を自動生成しない |
| CL-R-03 | 内部利用、第三者向けSaaS、OEM、再配布の許諾範囲を区別する。通常契約から再販売権等を推測しない |
| CL-R-04 | HELIXで作ったアプリは利用者側、HELIX自身・Package・Release Pack・Gene等の独自資産はRetryYN側と区別する。第一者・第三者・利用者所有・権利未確認を分離し、著作者と再許諾根拠を検証する。通知・元ライセンスを保持する。利用者アプリからGeneを抽出することを理由に元成果物の権利を移転させず、再利用・学習の許可を別途確認する |
| CL-R-05 | 適用開始release/source HEAD、license text digest、対象asset exact set、例外、契約版を束縛する。過去MIT版を遡及変更しない |
| CL-R-06 | LICENSE、package metadata、README、manifest、通知、配布先表示を対象版に対して一致させる。履歴版の証拠は保存する |
| CL-R-07 | 既存Release/Capability管理を再利用し、Module/Slice版・Bundle版・契約版を別軸で追跡する。全Module同時改版を必須にしない |
| CL-R-08 | 権利不明は該当資産の商用発効・配布を止める。無関係な既存開発・検証を一律停止せず、法定の権利を上書きしたと扱わない |
| CL-R-09 | clean consumerの導入・更新・rollbackでもartifactとその許諾版を一致させる。rollbackで別版の許諾へ偽装しない |
| CL-R-10 | 最終条文、権利者、適用開始版の確認と既存公開承認を満たして発効する。候補文書mergeを契約発効・公開と数えない |

受入は[対応するL10候補](helix-commercial-license-acceptance.md)へ一対一に束縛する。

## 実施順と未決事項

1. 本要求・受入候補を独立検収し、既存要求へ正本化する。
2. コード・文書・スキル等の全対象台帳を作り、由来・contributor・第三者条件を確認する。
3. 共通契約の最終条文と提供条件を確定する。契約主体、価格、期間、解約・更新、責任範囲、準拠法は未確定。法務確認対象とする。
4. 専用変更でLICENSEと各配布surfaceを一緒に切り替え、既存builder/consumer検証へ接続する。
5. 必要な公開承認後、対象版を配布しL12運用で表示・更新・rollbackを確認する。

非対象: AGPLへの独自制限追記、過去許諾の撤回、第三者権利の取得宣言、商標登録の推定、課金・DRM・通信認証の新規実装。
source非公開化は契約変更と別のアクセス管理操作であり、本PRから実行しない。
