# 要求ステージの総合検証

## 目的と対象

[PO原文](../../sources/requirements-stage-po-handoff-original-2026-09-27.md)の手順3に対応する判断材料である。対象はHARNESS、OS、BRAIN、LABO、INTELLIGENCE、SECURITY、INFRASTRUCTURE、CONNECTの8機構。Web／WEB-OSの1.x要求は対象外とし、既存候補にある後続版・条件付き接続は削除しない。

本資料は要求本文の代替ではない。8機構の現行L1・L2・L11、機構内の監査・解消記録、横断監査・解消記録を基に、要求段階で整理した境界とL3へ渡す事項を結ぶ。L1確定、L2合意、L3承認、実装・実行許可、releaseを生成しない。

## 今回確認する範囲

1. **責務と出力を区別する。** INTの案・同corpus適性比較、OSの割当・作業状態、Workerの実行、LABOの履歴水準・効果評価を同じ責務へ畳まない。HARNESSの共通検証契約と各要求ownerの意味oracleを区別する。
2. **開始条件と実行後の証拠を区別する。** 初回作業は未評価を保持して開始できる既決経路へ結び、後続の結果受領を開始前提にしない。proposal単体、選択された相談・実行、構成体、効果比較を別々に判定する。
3. **意味を保って個別交換する。** 契約版・scope・端点owner・未完義務を保持し、影響する範囲をstale化する。互換性の再照合と有効な送信許可を混同しない。
4. **過剰な停止条件を追加しない。** SECURITYは選択操作の既存制約を適用し、通常作業の毎回人間確認を新設しない。INFRAの独立OOB復旧と、通常のOS割当経路を分ける。1.0の最低18項目を減らさない。
5. **全体範囲と順序を区別する。** 214件の1.0候補を一度ずつ配属する。後続版33件、Web source条件付き3件、routing/移管宣言22件を別に保持する。SECURITY-026の1.0算入はGuard/Bot責務境界に限定する。段の全件完了を次段の一律gateにしない。
6. **具体値は根拠付きのL3要件候補へ渡す。** 数値・許容値・予算・受渡し項目/形式/版・実現可能性・移行互換性等を列挙する。通常の技術導出に新しい個別承認手続きを設けず、意味・scope・owner・版の矛盾はHARNESS-L2-003/004による既存の差戻しへ結ぶ。

## 残る判断と限界

- 8機構の対象revisionに対するL1確定・L2合意と候補の採用/保留/不採用は、総合検証の取込み後に立てる機構別確認PRでPOが判断する。HARNESSの製品/CORE/共通部品への所属候補等、上流に残る論点はL3一覧に明記した。
- 実装順の選択は確認PRの後、要件段階開始時に判断する。基本unitを先に広げる案と、狭いscopeのWorker支援・test生成へ早期投資する推奨案を比較する。候補の範囲や既決の初回経路は問い直さない。
- 旧source atomの後継割当には未完が残る。272宣言の分類一致や214候補の配属網羅を、旧資産の全条件移管・損失なしの証拠へ変換しない。既存の引継ぎ台帳と未完状態を保全する。
- 本照合は静的な文書・revision・ID・境界の確認である。L11の実行結果、実装の成立、実測の性能や効果を示さない。旧CI・旧hook・旧runtime・旧CLIを使わない。
