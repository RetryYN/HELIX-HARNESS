# FT-GOV-DEVELOPMENT-ENVIRONMENT-001

作業種別: 新世代の最小開発環境の再現手順・依存管理・検証経路を整理する

作業内容: HELIX自身の最初の開発対象について、同じ手順で環境を用意し、一つの変更を実装・検証・独立reviewできる最小構成を整理する。現行の開発repoに存在する文書整理・GitHub review・editor設定と、未構築の製品実装・検証環境を区別して棚卸しする。Python／Node等の実行環境と版、依存管理・lock、対象OS、セットアップ・更新・復旧手順、必要な環境変数の名前、セットアップの成立を確かめる方法を対象設計から導出する。secretやcredentialの値は記録しない。

作業内容: 選択した最小対象の責務に沿ってコード・検証設計・testの配置、Pythonの意味処理と外部作用を担う境界、型検査・lint・formatter・testの実行経路を整理する。ローカルでの検証を起点に、対象revision・実行環境・結果・独立reviewの対応を追えるようにする。具体的な言語版・ツール・設定・test oracleは、対応する要件と設計・検証から導出し、現行環境にインストール済みであることや旧設定の存在だけで採用しない。

作業内容: 文書規則の整備、最小対象の要件化、設計に基づく設定確定、開発・検証環境の構築という順序と、各段階で必要な入力・成果・未確定事項を既存ロードマップへ対応付ける。クリーンな作業領域からの再現、依存や版の不一致、セットアップ・検証失敗時の戻し先を、後続の環境構築で確かめる材料として整理する。大規模インフラ・Bot・全資産移管の完成を最初の開発の一律条件にせず、選択した対象で必要な安全・接続・資源・計測の範囲を特定する。

正本の案内: [現行作業入口](../new-generation-start-here.md)、[GitHub上流運用モデル](../github-upstream-operating-model.md)、[最小内部循環のロードマップ](../requirements-first-roadmap.md)、対象別L2／L11と判断記録を読む。文書・配置・規律本文の集約は #2903、最初の開発範囲と受入条件は #2846、Python意味sourceの抽出と処理は #1801／#1799、製品のbot・admission CIは #1837 の関連作業として区別する。本作業はそれらの要求・設計を代行せず、対象開発で使う環境へ接続する材料を整理する。
