# FT-TECH-RESEARCH-COVERAGE-001 — 技術選定入力の不足を自己提案し検証する

作業種別: research / 入力被覆監査

利用者の追加指示に従い、[技術候補入力一覧](../technology-strengthening-intake.json)のT01〜T10を既存要求/旧失敗/現行設計へ照合し、候補名だけでは抜ける観点を調べる。提案は同一覧のP01〜P06へ、既存要求revision・根拠・影響・検証方法・戻し先と未完を記録する。

- P01: 要求/版/選択経路/依存/対設計への対応を具体化する案を比較する。
- P02: 非機能・測定・環境互換性・選択UIの利用を具体化する案を比較する。
- P03: 保存/索引/backupの実復旧と移行を具体化する案を比較する。
- P04: 検査/開発tool自身の供給網と権限を具体化する案を比較する。
- P05: 独立評価の母数/oracleとAIの停止/費用を具体化する案を比較する。
- P06: 更新後再評価・旧版/利用履歴・運用を具体化する案を比較する。

既存上流と旧sourceへの静的照合と独立reviewを行い、実評価未実施を保持する。要求意味/固定閾値/一律gate/採用/新機構/操作許可は新設せず、意味変更が必要なものだけ既存authority経路へ戻す。全92親430対の基本/詳細/実装準備と最終監査の目標は縮めない。元の入力整理ticketは上書きしない。
