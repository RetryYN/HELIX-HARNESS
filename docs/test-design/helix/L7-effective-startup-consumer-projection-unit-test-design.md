# Effective Agent Startup consumer投影 L7検証設計

現行canonical pair `L6↔L7`に従う。旧L8命名へ新しいpairを増やさず、unit test粒度を本L7文書で所有する。

| U-ID | 対象 | 反例と期待結果 | test citation |
| --- | --- | --- | --- |
| U-STARTUP-CONSUMER-001 | source/template/generated consumer exact bytes | clean setup rendererの出力を別内容へ変えるとdigest mismatchで拒否 | `tests/setup.test.ts` |
| U-STARTUP-CONSUMER-002 | capability guidance state | blockedなlegacy teamをactive guidanceへ追加する、またはblocked entry自体を隠すと拒否 | `tests/setup.test.ts` |
| U-STARTUP-CONSUMER-003 | read order／hook／roster／digest | Requirement Markdown first-read、旧hook path、roster欠落、generated byte追加を個別に拒否 | `tests/setup.test.ts` |
| U-STARTUP-CONSUMER-004 | materialized consumer packet | setup後のpacketを改竄すると`helix doctor --profile consumer`が拒否 | `tests/doctor.test.ts` |

検証はproduction `verifyConsumerStartupProjection`を直接使う。test専用parserや期待件数だけでgreen化しない。clean consumer smokeは`planHelixProjectSetup`と`emitSetup`を通し、実際のtarget pathに生成されたpacketを読み戻す。

mutationでは、(1) blocked capabilityへのguidance追加、(2) Requirement IR first-readの置換、(3) hook surface置換、(4) roster entry削除、(5) generated bytes driftをそれぞれ独立に投入し、対応failureをkillする。
