### FR-OS-014 — HELIX段階の構成、再現、検証と切戻し

OSは、固定L2-014の内部段階releaseについて、stage identityと範囲、同じHARNESS pack体系から選択したpack/dependency、configuration/data format、対応environment、capabilityと限界、範囲内acceptance evidence、更新・切戻し条件を一組として記録し、宣言範囲の端から端作業・人の担当工程・状態継承・自己依存なしを追跡する。stageの受入・統合・更新・切戻し・運用検証をpack単体の結果から分離し、1.0到達判定とも分ける。OSはHARNESS契約、SECURITY authority/policy、INFRASTRUCTURE実資源・復旧能力、要求ownerの意味判断を代行しない。外部公開とHARNESSサービス⑥の製品releaseはこの親の対象外である。

**版・意味境界**: `v0.x`等はHELIX内部stageを識別し、公開semver/tagではない。`v1.0`は1.0到達判定を通った構成の表記で、外部公開許可を含まない。stage受入はL2が挙げるscope、品質条件、必要な安全依存を弱めず、未成立能力を「できないこと」に含める。INFRASTRUCTURE-L1-023は1.0より後・版未定として対象外のまま保つ。

**担当**: OSはstageの構成管理・生成・検証・配布・rollback運転と対応証拠を束ねる。HARNESSはpack boundary/call contract/verification-and-acceptance contractを定める。INFRASTRUCTUREはL1-017/018のbackup・restore、L1-019のrollback targetとdata互換、L1-020の独立復旧、L1-022の稼働環境identityと構成を定める。stage一般の環境health確認を追加しない。SECURITYは、固定親の資格情報方針と、対象scopeで選択された操作に必要なcredential/egress/operation authority条件を持つ。各ownerの契約・実状態が不足しているときOSはunknown/unfinishedを保ち、該当ownerへ返す。人手作業は同じ必須契約・authority・evidenceを代替せず、scope内工程の担当・結果を記録する。

- **AC-OS-029-01 normal — consultationなし**: L11-029の作業前test/instruction準備経路を用いる。INTELLIGENCEがapproved request/designとHARNESS-022 oracleからtest/instruction candidateをsource revisionへ結び、OSが元Workerのticketを開始し、元Workerが実装・検証する。support/consultを選ばないことは、承認済みrequirement/pair/oracleの適用、実際の検証実行とそのsource-bound result receipt、必要な独立review/owner receiptの義務を消さない。選択相談がないためOS-028 receiptは存在せず、要求もしない。作者とは別の独立reviewerが実際の差分/current resultを確認し、findingがあれば元Workerへ返す。
- **AC-OS-029-02 normal — consultationあり**: L11-029のPATCH oracle fixtureをそのまま用いる。既存oracleはdraftの有効変更を受け入れて永続化し、approvedの編集を拒否して永続値を変更せず、無関係field/stateは不変とする。実consultを選んだ場合にだけOS-028の有効なresponse/return receiptを加え、元Workerが修正し、OS-020の許可済み経路でHARNESS-022に結ばれた結果を得る。独立review receiptは別ownerから受け取る。
- **AC-OS-029-03 current-head review normal**: 修正でHEADが変わったとき、review receiptはcurrent exact HEAD/base/task scope/HARNESS oracle/current resultを束縛し、reviewerは元Worker・支援者・test authorとidentity/context/authorityが別であり、unresolved findingが0件である。これは独立review条件だけを満たす。Verified candidateは、適用される既存HARNESS各段階のevidence/resultと必要なowner receiptも同一revisionで揃った場合に限る。Acceptedは別に利用者acceptance receiptがある場合に限る。いずれのreceiptも不足・stale・不一致なら該当状態へ進めず、review findingがある場合は元Workerへ返し、再修正後は新HEADに対する新receiptを得る。review finding 0件だけで他HARNESS段階、Verified、Accepted、composite全体の完了を生成しない。
- **AC-OS-029-04 negative**: proposalだけ・handoffだけでcompositeを閉じる、consultなしで028 receiptを要求する／実consult後にreceiptを欠く、test helperが固定oracleと異なる期待を使う、consultantをindependent reviewerにする、旧HEAD result/reviewをcurrent HEADへ流用する、CI greenのみでAcceptedにする、AI案がrequirement/test/oracle/authorityを変更することを拒む。さらに独立review finding 0件のみで他のHARNESS段階evidenceなしにVerifiedへ進める場合、およびVerified/current reviewのみで利用者acceptance receiptなしにAcceptedへ進める場合を別negativeにする。L11の各誤りを別CASEにする。
- **AC-OS-029-05 unseen/return**: 未見endpointで既存oracleの適用可能性が不明なら、類似性で一般化せず設計/requirement ownerへ不足を返しverification candidateに留める。assignment/execution/repairは元Worker/OS、oracle/要求意味はHARNESS/要求owner、authorityはSECURITY、environment/resourceはINFRASTRUCTURE、提案/相談不足はINTELLIGENCE/OSへ戻す。
- **AC-OS-029-06 composite/unfinished**: 相談を選ばない通常経路ではproposal → 相談前の元Worker初回差分 → HARNESS-linked result → independent review → 必要なowner receiptを結ぶ。実consultを選んだ再作業経路では、proposalと相談前の元Worker初回失敗差分を先に固定し、OS authorization → consult request → response/return receipt → 元Workerによる相談後修正差分 → HARNESS-linked result → independent review → 必要なowner receiptの順に、同一scope/revisionと各artifactを結ぶ。相談前の初回失敗差分は相談結果や修正差分とみなさない。finding時は元Workerの再作業/retestをcurrent HEADへ結び、budget/期限/stop到達時はunfinishedを示す。どのsubunit単独もpassにしない。結果/effect/attempt/cost/time/unfinished/resumeを保ち、fixed cycle countや成功扱いを追加しない。
