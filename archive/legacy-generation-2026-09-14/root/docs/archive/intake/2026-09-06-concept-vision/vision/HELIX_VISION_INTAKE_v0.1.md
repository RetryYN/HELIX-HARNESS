# HELIXビジョン v0.1 — 取込メモ

## 目的
本会話の長期構想を、現在のアーキテクチャカタログv0.6と区別して保全する。ビジョン版1.0〜5.0を公開SemVerや既存G1〜G5評価へ自動変換しない。本メモは即時実装・公開の指示ではない。

## 保持する方向
HELIX 1.0を現在構想の最初の完成という作業上の節目に置き、その確定対象は別途定義する。以降は本体とHELIX-Webが並行して進み、Release Pack、Connector、外部推薦、モデル／HDA、Intelligence、System Compilerで交差する。

本体2.0は外部開発データの分解・根拠付き推薦、3.0はHELIXデータを使うLLMチューニング、4.0はチューニングした小型ローカルモデル群とKimi級の大規模公開モデル等による動的開発フロー構築、5.0は共同要件定義の確定後に検証付きシステムを納品するSystem Compilerを構想する。ゼロからの基盤モデル事前学習を必須にしない。

本体1.0〜2.5の進展帯でHELIX-WebをAI開発SaaSとして展開し、初期はConnector型とする。Web3は調整済みモデルを分散サーバーから呼び出すHELIX Developer Assistance（HDA）。自分のAIログインを使う体験はプロバイダー別の公式な接続・利用条件の確認を前提にする。

利用者が保守・改修を自分で行えることを最重要の価値とする。到達時期は未決定とし、以前の「2.5で可能」等を確約に変えない。画面・動作の共同確認から仕様へ展開し、見えない制約は必要な範囲で確認する。確定後の変更は影響限定の再入・差分再コンパイルで扱う。

HELIX-FACTORYは本体以外の事業展開の傘。Web、MARKETING、その他の商品を並行して育てる。マーケティングは市場からの企画と利用ログからの改修の両方を扱い、変更の根拠・目的をHELIXへ渡す。製品課題とHELIX自己改善は別対象にする。

## 今回の境界
v0.6のPackage＝開発責務＋最小基盤を維持し、既存Moduleの所有・Sliceの昇格・Bundleの構成を変更しない。13候補を13公開製品として扱わない。モデル・学習・Factory全体を外部Packageへ無差別に同梱しない。

今は未来構想を理由に新規統合を強制しない。1.0以降、HELIXを使ってWeb・MARKETING等の並行開発を磨き、小さな根拠付き提案の受渡しから接続する。既存案件の成果を破棄・停止する指示でもない。

## 後続の要求化
対象の節目と利用範囲を選ぶ → 既存owner・契約・依存を照合 → 不足部分だけ要求差分へ → 品質／安全／データ権利と人間境界を定義 → 局所検証 → 限定提供 → 結果を再観測する。

サービスの利用と学習同意を分離する。学習用・評価用データ、テナント・プロジェクト、公式認証経路、秘密情報、既存データの移行と回復を確認する。具体モデル、費用・品質閾値、公開版、日付、課金は本書から補完しない。

## 非対象
全Issueの再freeze、既存承認の創作・取消、コードの物理移動・削除、新規DB／graph／builder／承認engineの一律新設、プロバイダー認証の移送、モデル学習や推論サーバー起動、tag／publish／production apply。本ビジョンの保存だけを実装開始や公開許可とみなさない。
